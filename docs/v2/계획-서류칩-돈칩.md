# 계획 — 서류 칩(2단계) + 돈 칩 통일 · 청구 열 (2026-10-20 결정, §95 예정)

> 사용자 결정(10/20 저녁): ① 청구일과 청구서가 떨어져 있어 불편 → **청구일 열을 '청구' 열로**(청구일 + 청구서 칩). ② 결의 완료의 뜻이 헷갈림 → 양쪽을 **서류 칩 + 돈 칩** 틀로 통일. ③ 서류 칩은 **중간 단계 없이 2단계**(전 / 완료). 결의 칩은 서류만, 비용 인정은 새 **지출** 돈 칩으로.
> 이 문서는 구현 세션(Opus)용 인수인계. 끝나면 `프론트엔드-변경사항.md` §95로 옮기고 삭제한다. 계획만 세운 상태, 코드 변경 없음.

## 0. 결과 화면

| 열 | 내용 |
|---|---|
| 청구 | 청구일 + 서류 칩 **청구 전 / 청구 완료** |
| 매출금액 | 금액 + 돈 칩 **입금 전 / 입금 MM-DD** (지금 그대로) |
| 비용 · 결의 · 지출 | 비용 + 업체명·분류 + 서류 칩 **결의 전 / 결의 완료** + 돈 칩 **지출 전 / 지출 MM-DD** + '+ 비용' |

- 서류 칩 둘은 집계 영향 없음. 돈 칩만 숫자를 움직인다: 미수금 = 청구 완료 + 입금 전, **비용 인정 = 지출 완료 또는 회차 입금 완료**(종전 '결의 완료' 자리를 '지출 완료'가 대신함).
- 비용 줄은 청구 열에 날짜만(서류 칩 없음), 매출 칸 '—'.
- 오늘(§94) 넣은 '진행중'은 쓰지 않는다. 운영에 진행중 행: 청구 0건, 결의 1건 → 마이그레이션에서 '전'으로 되돌리고 건수를 기록(사용자에게 알림).

## 1. 데이터

마이그레이션 `2026_10_2X_000000_add_cost_paid_to_contracts`(멱등):
- `contracts.cost_paid` boolean default false — 지출 완료(돈 나감). 백필 `cost_paid = expense_requested`(= 결의 완료였던 행은 모두 지출 완료) → 비용 합계 불변.
- `invoice_status`·`expense_status`의 `in_progress` → `none`(건수 출력). 값 집합은 `none`·`done` 둘만 쓴다(컬럼·상수는 유지, 라벨 '전'·'완료').
- 지출일은 기존 `cost_date` 그대로 = 돈이 나간 날(비우면 청구일). 운영 지출일 입력 0건.

## 2. 서버

1. `Contract`
   - `BILLING_STATUSES = ['none' => '전', 'done' => '완료']` (in_progress 제거). 응답 `invoiceStatus`·`expenseStatus`('전'/'완료'), 새로 `costPaid`(bool).
   - **saving 훅 변경**: `expense_requested`는 이제 `cost_paid`에서 파생(`expense_requested = cost_paid`). `expense_status`는 서류 상태라 불리언과 끊는다. `invoiced = invoice_status === 'done'`은 그대로. 불리언만 쓰는 구 경로(결재 승인 finalize 등)는 `expense_requested` → `cost_paid`로 따라오게 역방향도 유지.
   - `scopeExpenseRecognized`·소비처 10곳 무변경(`expense_requested`를 계속 읽음 = 지출 완료).
2. `ContractController`
   - `update`: `invoiceStatus`·`expenseStatus` ∈ ['전','완료'], 새 `costPaid`(bool) + `costDate`(지출 완료 시 날짜, 없으면 청구일). 지출 완료는 비용 > 0일 때만(422). 되돌리기(costPaid=false)는 지출일을 유지(예정일). 이력 '청구서'·'지출결의서'('전'→'완료'), '지출'('지출 전'→'지출 완료 YYYY-MM-DD'). 비용 달(지출일) 변경 시 양쪽 스냅숏 재계산(이미 costBefore/After 로직 있음 — cost_paid 토글도 재계산 대상에 포함).
   - `store`: `installments.*.expenseStatus`('전'/'완료'), `installments.*.costPaid`, `costDate`(이미 있음). 구 `expenseRequested` 불리언은 costPaid로 매핑.
   - `bulk`: `invoice_status`·`expense_status`의 value ∈ ['전','완료']. 새 액션 `cost_paid`(+ `costDate` 필수, 일괄 완료처럼 날짜 1개) — 비용 없는 행·비용 줄 아닌 행 중 비용 0 제외. `cost_unpaid`(지출 전으로). 스냅숏 재계산.
   - 휴지통 목록·백업에 `cost_paid`.
   - `ApprovalController::finalize`(미도입이지만 코드 보존): `expense_requested = true` 쓰면 훅이 cost_paid도 켬 — 동작 유지.
3. 검증: migrate(백필 수 = expense_requested 수), tinker로 지출 완료 토글 → expense_requested 파생, 결의 완료만으로는 비용 인정 안 됨(expense_requested false), in_progress 0건.

## 3. 프론트

- 타입: `BillingStatus = '전' | '완료'`, `BILLING_STATUSES` 2종, `Contract.costPaid`, `updateContract` patch `costPaid`·`costDate`, `InstallmentInput.costPaid`, `bulkContracts` action `cost_paid`(costDate)·`cost_unpaid`.
- **표**(`renderRow`): 청구일 셀 → 청구 열(날짜 + `BillingChip` 청구, 비용 줄은 날짜만). 매출 셀: 금액 + 입금 칩(청구 칩 제거). 비용 셀: 비용 + 업체·분류 + 결의 칩 + **지출 칩**(`지출 전` 클릭 → 날짜 팝오버(기본 지출일 또는 청구일, [오늘]·[청구일] 퀵픽) → `costPaid: true, costDate` / `지출 MM-DD` 클릭 → 지출 전). '지출 MM-DD' 서브라인은 칩이 대신하므로 제거. 머리글 '청구' / '매출금액 · 입금' / '비용 · 결의 · 지출'. 폭: 청구 열 +2%, 매출 −2%.
- `BillingChip`: 2단계 토글(전 ↔ 완료). 청구 완료 + 입금 전 = 주황(미수금).
- 일괄 바: 청구 [전|완료], 결의 [전|완료], **지출 처리(지출일 1개 지정 다이얼로그, 일괄 완료와 같은 모양)**, 지출 취소. 선택에 비용 있는 줄 없으면 결의·지출 비활성.
- 필터: 청구(전/완료), 결의(전/완료), **지출(전/완료)**.
- 카드·집계: `sumActualCost`·`expectedCostRows`는 `expenseRequested` 그대로(= 지출 완료). 묶음 행 '결의서 n/m' → '지출 n/m'(서버 `expense_done_count`는 `cost_paid` 기준으로).
- **비용 줄 편집기**(`CostRowsEditor`, 입력·수정 창): 줄마다 지출일 · 비용 · 업체명 · 분류 · 결의(전/완료) · **지출(전/완료)**. 지출 완료면 지출일 칸이 돈 나간 날. 수정 창 비용 줄(costOnly) 폼도 결의 셀렉트 + 지출 체크·지출일.
- '+ 비용' 창(`AddCostDialog`): 결의 상태 셀렉트 → 결의(전/완료) + 지출(전/완료) 체크 + 지출일.
- CSV: '청구 상태'·'결의 상태'·**'지출'(지출 완료/전)**·'지출일'.
- 안내 문구: 표 아래, 수정 창, 입력 가이드 — "청구서·결의서는 서류, 입금·지출이 돈. 돈 칩만 집계에 반영".
