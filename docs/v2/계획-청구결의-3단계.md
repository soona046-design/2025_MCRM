# 계획 — 청구서·결의서 3단계 상태(B안, 수동) + 매출 입력 팝업 매출/비용 탭 (2026-10-20)

> 사용자 결정(2026-10-20): ① **전자결재는 도입하지 않는다** — 청구·결의 상태를 결재 문서와 연동하지 않고 사람이 수동으로 바꾼다. ② 청구서·결의서 체크를 **[진행전 - 진행중 - 완료] 3단계로, 상태를 저장(B안)**. ③ 매출 입력 팝업도 표와 같이 비용을 여러 줄 입력하게 맞추고, 칸이 부족하면 **매출 / 비용 탭**으로 나눈다.
> 이 문서는 구현 세션(Opus)용 인수인계. 끝나면 `프론트엔드-변경사항.md` §94로 옮기고 삭제한다. 계획만 세운 상태이며 코드 변경은 없다.

## 0. 전제 — 집계는 건드리지 않는다

현재 `contracts.invoiced`·`expense_requested`(참/거짓)를 읽는 곳 10파일(Contract·ContractGroup 모델, ContractController, DashboardController, RevenueAnalyticsController, RecurringController, ApprovalController, MonthlySnapshots, RevenueMetrics, ReportService)은 전부 **참 = '완료'(전달됨·지출 인정)** 뜻으로만 읽는다. 그래서:

- 새 상태 칸을 **단일 원본**으로 두고, 기존 참/거짓 두 칸은 `상태 === 'done'`에서 **서버가 자동 파생**해 저장한다(모델 saving 훅). → 집계·미수금·스냅숏·보고서·정기 roll·결재 승인 코드는 **무변경**.
- 미수금 = 청구 '완료' + 진행 중 회차, 비용 인정 = 결의 '완료' 또는 회차 완료. 지금 규칙 그대로.
- '진행중'은 집계에 영향 없음. 뜻(가정, 사용자 확인 전): 청구서 = 작성 중·발송 전, 결의서 = 작성·승인 중·지출 전.

## 1. 데이터

마이그레이션 `2026_10_2X_000000_add_billing_status_to_contracts`(멱등, hasColumn 가드):
- `contracts.invoice_status` string(12) NOT NULL default `'none'`, `contracts.expense_status` 동일. 값 `none`(진행전) · `in_progress`(진행중) · `done`(완료).
- 백필: `invoiced = 1 → invoice_status = 'done'`, `expense_requested = 1 → expense_status = 'done'`, 나머지 `'none'`. 이력·수치 변화 없음. 참/거짓 컬럼은 **삭제하지 않는다**(파생 캐시로 유지).
- `Contract::BILLING_STATUSES = ['none' => '진행전', 'in_progress' => '진행중', 'done' => '완료']`.

## 2. 서버

1. `Contract` 모델
   - fillable에 두 컬럼. `booted()`에 `saving` 훅: ⓐ `invoice_status`가 dirty면 `invoiced = (status === 'done')`; ⓑ 상태는 안 바뀌고 `invoiced`만 dirty면(결재 승인·구 API 호환) `invoice_status = invoiced ? 'done' : 'none'`. expense도 동일. → 어느 쪽으로 써도 둘이 항상 일치.
   - `toFrontend()`에 `invoiceStatus`·`expenseStatus`(한글 라벨, 기존 `status`와 같은 방식). `invoiced`·`expenseRequested`는 그대로 내려 줌(프론트 미수금 판정 등 유지).
2. `ContractController`
   - `update`: `invoiceStatus`·`expenseStatus` ∈ 라벨 3종 검증. 비용 줄(`isCostOnly`)에 청구 상태 '진행중/완료' 요청 → 422. 비용 없는 행에 결의 상태 '진행중/완료' → 422. 이력 필드명 '청구서'·'지출결의서', 값은 라벨(진행전 → 진행중 등). 기존 `invoiced`·`expenseRequested`(불리언) 파라미터는 **당분간 유지**(완료↔진행전으로 매핑, 구 프론트 캐시 안전).
   - `store`: `installments.*.expenseStatus`(라벨, 기본 진행전)로 교체 — 기존 `expenseRequested` 불리언도 받아 매핑. 등록 이력에 상태가 진행전이 아니면 한 줄 추가.
   - `bulk`: 액션을 `invoice_status`·`expense_status` + `value`(라벨 3종)로 교체(기존 invoice/uninvoice/expense/unexpense는 제거 — 프론트만 소비). 제외 규칙: 비용 줄은 청구 상태 변경 제외, 비용 없는 행은 결의 상태 변경 제외. 이력 '(일괄)' 표기 유지.
   - `trash` 목록·`ContractTrashBackup`에 두 상태 추가.
   - `index`·`listQuery`·그룹 프리로드: 변경 없음(참/거짓 파생값 사용). 묶음 행 '결의서 n/m'의 n은 완료 수 그대로.
3. `ApprovalController::finalize`: **무변경**(불리언을 true로 쓰면 훅이 '완료'로 맞춤). 전자결재 미도입 결정에 따라 매출 현황 일괄 바의 **'청구서 작성'·'결의서 작성' 버튼은 제거**(결재 문서 메뉴·화면 자체는 남김 — 숨길지는 별도 결정, §6).
4. 검증: `php -l`, `php artisan migrate`(로컬 SQLite), tinker로 상태 3단계 전환 → 불리언 파생 확인, 불리언만 써도 상태가 따라오는지(훅 ⓑ), bulk 제외 규칙, 비용 줄 청구 상태 422. MySQL 주의: 기본값 `'none'` NOT NULL — 백필 UPDATE를 컬럼 추가 뒤 같은 마이그레이션에서.

## 3. 프론트 — 표·일괄·필터

파일: `src/lib/mock-revenue.ts`·`revenue-api.ts`(타입 `BillingStatus = '진행전' | '진행중' | '완료'`, `updateContract` patch에 `invoiceStatus`·`expenseStatus`, `bulkContracts(ids, action: 'invoice_status' | 'expense_status' | 'complete' | 'trash', value?)`), `src/app/(main)/revenue/page.tsx`.

- **칩**(매출 칸 '청구서', 비용 칸 '결의서'): 클릭마다 진행전 → 진행중 → 완료 → 진행전 순환(`toggleFlag` → `cycleStatus`). 표시: 진행전 = 회색 점선 테두리 '청구서', 진행중 = 파란 실선 테두리 '청구 진행중', 완료 = 지금 색(청구 완료 + 진행 중 회차 = 주황 미수금색, 그 외 파랑 / 결의 완료 = 초록) '청구 완료'·'결의 완료'. 툴팁에 다음 단계 안내("클릭 → 진행중").
- **일괄 바**: '청구서 ✔ / 청구서 해제 / 결의서 ✔ / 결의서 해제' 4개 → 두 묶음 `청구 [진행전 | 진행중 | 완료]`, `결의 [진행전 | 진행중 | 완료]`(세그먼트 버튼). 매출 줄 없으면 청구 묶음 비활성, 비용 있는 줄 없으면 결의 묶음 비활성. '청구서 작성'·'결의서 작성'(결재 기안) 버튼 제거, `composeApproval` 제거.
- **필터**: '청구 상태 · 전체/진행전/진행중/완료', '결의 상태 · 전체/…' 셀렉트 2개 추가(필터 줄이 길면 '구분' 옆 한 줄 접기). `isReceivable`·`isCarry`·카드 산식은 불리언 기준 그대로.
- **CSV**: '청구서'·'지출결의서' 열 값을 라벨(진행전/진행중/완료)로.
- 휴지통 화면: 상태 표시(선택).

## 4. 프론트 — 입력·수정 팝업을 매출 / 비용 탭으로

파일: `src/app/(main)/revenue/page.tsx`(`AddContractDialog`), `src/components/revenue/contract-ui.tsx`(`EditAmountDialog`·`AddCostDialog`·새 `CostRowsEditor`).

공통 부품 `CostRowsEditor`(비용 줄 목록 편집기): 줄마다 `지출일 · 비용 · 업체명 · 분류 · 결의 상태(진행전/진행중/완료) · 짝 회차 · 삭제`, 아래 `+ 비용 추가`. 표의 비용 칸과 같은 정보 구성.

- **AddContractDialog**(매출 직접 입력): 상단 고객 유형·고객 선택은 그대로. 그 아래 **탭 [매출 | 비용]**.
  - 매출 탭: 매출 유형(비정기/정기), 프로젝트, 회차 줄(청구일·매출금액·**한 줄 비용**은 유지 — 한 업체면 여기, 여러 업체면 비용 탭 안내 문구). 정기 폼의 월 비용·업체명·분류도 매출 탭.
  - 비용 탭: `CostRowsEditor`. 짝 회차 선택지는 매출 탭의 회차 번호(비정기) / 정기는 짝 없음(프로젝트 공통). 탭 머리에 건수·합계 배지("비용 2건 · ₩1,500,000").
  - 저장: 지금 `installments` 배열에 매출 줄 + 비용 줄(amount null, cost, vendor, costCategory, parentIndex, expenseStatus)로 한 번에 전송 — 서버 변경 없음(expenseStatus만 추가). 현재 '+ 비용 줄' 인라인 방식은 탭으로 대체.
- **EditAmountDialog**(연필, 매출 줄): **탭 [매출 | 비용]**.
  - 매출 탭: 청구일·상태·수금일·매출금액·청구 상태(셀렉트)·프로젝트(지금 내용).
  - 비용 탭: ① 이 회차 자체 비용(한 줄 비용: 비용·지출일·업체명·분류·결의 상태) ② **짝 비용 줄 목록**(이 회차를 parent로 둔 줄 — 목록·그룹 조회로 가져옴)을 `CostRowsEditor`로 수정·추가·휴지통. 저장 = 본 회차 `updateContract` + 바뀐 줄마다 `updateContract` + 새 줄 `addContract`(parentContractId) + 삭제 줄 `deleteContract`(확인 후). 실패 시 어느 줄에서 멈췄는지 토스트.
  - 비용 줄(`isCostOnly`)을 열면 탭 없이 지금의 '비용 수정' 폼 + 결의 상태 셀렉트.
- **AddCostDialog**('+ 비용'): 결의서 체크박스 → 결의 상태 셀렉트. 그대로 유지(빠른 추가용).
- 수정 창 폭: 탭으로 나누면 `max-w-sm` 유지 가능, 비용 탭 줄이 많으면 세로 스크롤(`max-h-[60vh]`).
